# 연애 플래그는 예외 처리되지 않습니다

세 휴머노이드와 일상을 보내며 관계를 선택하는 한국어 비주얼 노벨입니다. 현재 새 게임은 시나리오 v4를 사용합니다.

## 실행

Node.js 22.13 이상에서 `npm ci`, `npm start`를 실행한 뒤 http://127.0.0.1:3210 에 접속하세요. macOS에서는 `게임 실행.command`를 더블클릭해 전용 Chrome 창으로 실행할 수도 있습니다.

전용 창은 별도 브라우저 프로필과 자동재생 옵션을 사용합니다. 일반 브라우저에서는 소리 있는 자동재생이 차단될 수 있으며, 이때 안내 후 첫 입력에서 재시도합니다. OP는 표지 진입 시 재생을 시도하고 이름 입력·갤러리·불러오기 선택에서는 유지하며, 실제 이야기에 들어가면 정지합니다. 표지는 양옆 배경을 확장한 16:9 이미지를 사용합니다.

## 7개 에피소드

| 편 | 제목 | 이야기 |
|---|---|---|
| 1 | 네..? 교수님 진심이세요..? | 첫 만남과 세 명 각각의 첫 자유대화 |
| 2 | 데이트라 쓰고 연구라 읽는다 | 함께 먹는 점심, 서로 다른 날의 개인 외출 |
| 3 | 바다에서 일어난 일 | 넷이 함께 떠난 바다, 네무 → 린카 → 시오리 CG, 귀가 후 독백 |
| 4 | 너네.. 방수 되는 로봇 맞지? | 우산을 가져갈 메인 히로인 선택, 비를 피하는 시간 |
| 5 | 이정도까지 프로그래밍 되어있다고? | 선택한 히로인과의 갈등, 엑스트라와의 사건 및 화해 선택 |
| 6 | 연구를 마치며 | 축제 데이트와 관계 회복 기회, 기억에 관한 위기 |
| 7 | 내일도, 같은 이름으로 | 마지막 옥상 대화와 관계 의사, 최종 결정 |

세 명의 개인 외출 뒤 주인공과 히로인 셋이 함께 바다에 갑니다. 한 번의 바다 에피소드에서 네무 → 린카 → 시오리 순으로 세 CG를 모두 볼 수 있습니다. 귀가와 검은 화면 독백 뒤 비 오는 날 상대를 고르며, 이후 갈등과 화해 → 축제는 선택한 그 한 명과만 진행합니다. 시오리는 돌봄과 자기 바람, 린카는 둘만의 모습과 사생활, 네무는 타인의 시선과 스스로 선택하는 마음을 중심으로 전개됩니다. 네무의 게임 취향은 사용하지 않습니다.

갈등·화해와 바다는 고정 대사 및 3지선다로 진행하며 AI 대화가 없습니다. 자유대화는 첫 만남 8턴×3명, 개인 외출 6턴×3명, 비 6턴, 축제 6턴, 옥상 10턴으로 **한 판 최대 64회**입니다. 실패·재시도에 따른 추가 제공자 요청은 별도입니다. 턴 수는 게임 화면에 표시하지 않습니다.

## 호감도와 엔딩

초기 호감도는 캐릭터별 30이며 0~100 범위입니다. 고정 선택과 자유대화가 점수를 바꿉니다. 자유대화의 구간별 상승 상한은 첫 만남 8, 외출 6, 비 4, 축제 4, 옥상 6입니다. AI가 제안한 변화량과 실제 적용량은 다를 수 있습니다.

기억 보존을 선택하려면 선택 상대의 **호감도 60 이상 + 갈등 해결 + 마지막 관계 의사 확인**이 필요합니다. 관계 의사는 옥상 자유대화 뒤 고정 선택지에서 직접 확인하므로 대화를 모두 스킵해도 좋은 선택을 이어 가면 조건을 충족할 수 있습니다. 마지막 관계 거절은 높은 호감도보다 우선합니다. 해결하지 못한 갈등은 옥상의 구체적인 선택으로 회복할 수 있습니다.

엔딩은 배드·노말·해피 세 갈래입니다. 먼저 옥상 이후 관계 기억을 지킬지 초기화할지 결정합니다. 초기화를 승인하면 **배드 「또 다시 혼자」**로, 세 히로인이 함께한 관계를 잊고 논문을 제출하는 원래 기억 삭제 장면이 나옵니다. 기억 보존을 선택하면 수정과 안정화가 성공하고 세 사람의 기억을 지킵니다. 교수의 3년 후속 연구·동거 제안 뒤 다시 선택합니다.

동거와 후속 연구를 거절하면 **노말 「로봇은 로봇일 뿐」**입니다. 히로인 없이 대학 복도에서 주인공이 독백하고, 마지막 보고서를 제출하며 연구를 마무리합니다. 연애·다음 만남을 약속하지 않습니다. 동거를 선택하면 기존 캐릭터별 **해피엔딩**으로 이어집니다. 아침 장면과 `assets/moments/*-happymorning.png`는 유지하며, 본 아침 CG는 기억의 순간에 저장됩니다. 직접 수정한 동거 엔딩 제목·대사도 유지합니다. 분류는 3갈래이며 갤러리에는 해피 3명 + 공통 노말 + 공통 배드 총 5개 엔딩이 표시됩니다.

## 자유대화 기록과 행동지문

한 세이브에서 나눈 자유대화 원문을 히로인별로 모두 보관합니다. 장면 전환이나 40메시지 경과로 오래된 원문을 지우지 않으며, 고정 대사와 자유대화를 포함한 기억 로그도 같은 세이브에 남습니다. 다른 세이브나 다른 히로인의 사적인 대화와 합치지 않습니다. 현재 64회 전부를 입력·답변 최대 길이로 채운 모의 데이터에서 대화 기록은 약 0.6MB였습니다. 이미 이전 버전에서 삭제된 오래된 원문을 복원하지는 못합니다.

토큰 비용을 줄이기 위해 OpenAI에는 최근 20개 메시지와 구조화된 기억·요약을 전송합니다. 전체 원문은 세이브 안에 보관합니다. 로컬 API는 긴 기록을 다룰 수 있도록 최대 96메시지, 대화 요청만 512KiB를 허용하며 다른 요청은 기존 64KiB 제한을 유지합니다.

AI 답변은 대사와 함께 소괄호 `( )` 안에 상황에 맞는 짧은 행동지문을 1~2개 넣도록 지시합니다. 사용자가 입력하는 `**행동 지문**` 방식은 그대로입니다. 체험 모드도 괄호 행동지문을 표시합니다.

## 저장과 그림

왼쪽 위 설정에서 저장·불러오기·기억·화면·음악을 관리합니다. 저장 슬롯에는 당시 세 명의 호감도와 에피소드가 표시됩니다. 자동 저장, 수동 3슬롯, 마지막 옥상 대화 전과 최종 결정 다시 보기를 지원합니다. 저장·불러오기 창의 슬롯별 삭제 버튼으로 세이브를 개별 삭제할 수 있습니다. 확인 후 삭제하며 다른 슬롯·설정·해금 그림은 유지합니다. 플레이 중 자동 저장은 이후 진행 시 다시 생성될 수 있습니다. 메인 화면 이동·덮어쓰기·불러오기·스킵에는 해당 동작의 확인 안내가 있습니다.

읽고 넘긴 고정 대사는 `←` 또는 `Backspace`로 다시 볼 수 있습니다. `→`·클릭으로 앞으로 읽거나 ‘현재 진행으로’·Esc로 복귀합니다. 다시 보기는 호감도·선택·AI 요청을 되돌리거나 반복하지 않습니다. 현재 플레이 중 최근 250개 화면을 보관하며 새 게임·불러오기·페이지 새로고침 때 초기화됩니다. 입력창에서는 기존 키 입력 동작을 유지합니다.

게임 세이브는 같은 브라우저·같은 주소의 로컬 저장소에 보관됩니다. 기존 v4 저장은 점수와 선택 상대를 유지해 새 순서에 연결하며 이미 겪은 갈등은 반복하지 않습니다. 이전 바다 진행 중 저장은 새 단체 바다 시작으로 연결하고, 기존 바다 선택을 이미 했다면 재진행 점수를 더하지 않습니다. 새 순서 전체를 보려면 새 이야기로 시작하세요. 기존 v3 저장은 기존 시나리오로 이어지며, 새 7편을 보려면 새 이야기를 시작하세요. 기존 세이브는 자동 삭제하지 않습니다.

기억의 순간에는 데이트·비·축제·바다의 캐릭터별 CG 총 12장이 있으며 실제로 본 그림만 열립니다. 개인 외출 CG도 대사에 맞춰 시작합니다. 시오리는 흰 머리핀을 바라보는 순간 CG가 나오며 가게 안 선택·대화까지 유지하고, 가게를 나오면 기본 화면으로 돌아갑니다. 린카는 소매를 당기는 순간, 네무는 자신을 봐도 괜찮다고 말하는 순간 CG가 나오며 클릭 후 대화 3회를 읽고 기본 화면의 자유대화로 이어집니다. 두 사람의 작별 선택은 자유대화 뒤에 나옵니다.

바다 CG는 선택 상대와 관계없이 세 장 모두 장면을 본 뒤 해금됩니다. 네무는 뒤돌아보는 순간 그림이 먼저 나오고 클릭 후 CG 위에서 세 번 대화한 뒤 스탠딩으로 이어집니다. 린카·시오리는 그림만 먼저 보여 준 뒤 CG 위 대화 세 번과 선택지를 진행하고, 선택하면 일반 화면으로 돌아옵니다. 시오리 CG는 “알겠어. 같이 치우고 있잖아.” 바로 다음에 시작됩니다. 바다 스탠딩은 기존 기본 스탠딩을 바탕으로 옷만 변경한 캐릭터당 1장, 총 3장입니다. 바다 장면에서만 사용하고 귀가할 때 원래 옷으로 돌아갑니다. 제작 기록은 `asset-revision4-manifest.json`에 있습니다.

## AI 연결

`.env.local`에 `OPENAI_API_KEY`를 설정하고 서버를 재시작한 다음 게임 설정에서 AI 자유대화를 선택하세요. 모델은 `OPENAI_MODEL`로 설정하며 현재 기본값은 `gpt-5.4-mini`입니다. 키는 서버에만 보관합니다.

체험 모드는 미리 작성한 반응으로 동작합니다. AI 모드 오류가 나면 입력을 보존하고 턴·호감도를 소비하지 않으며, 자동으로 체험 모드로 바꾸지 않습니다. 이번 개편 검증에서는 유료 OpenAI 호출을 실행하지 않았습니다.

## 관리자 대화 기록

관리자 주소는 http://127.0.0.1:3210/admin (로컬 다운로드판) 입니다. 첫 실행 때 비밀번호를 생성해 **`private-data/관리자-접속정보.txt`**에 저장합니다. 이 파일과 `private-data`는 공개 폴더 밖에 있습니다. 비밀번호를 변경하려면 서버를 종료하고 `node scripts/admin-password.mjs`를 실행한 뒤 재시작하세요. `ADMIN_PASSWORD`는 최초 인증 파일 생성 때만 적용됩니다.

플레이어에게 첫 전송 전 수집 항목·목적·운영자 열람·30일 보관을 안내하고 동의받습니다. 동의하지 않아도 고정 이야기와 선택지로 진행할 수 있습니다. AI·체험 모드 모두 전송한 닉네임과 메시지, 답변, 장면, 결과 상태를 기록합니다. 전송하지 않은 초안은 수집하지 않습니다. 입력문에 개인정보나 비밀번호를 쓰지 않도록 안내합니다.

닉네임 또는 입력문 검색 → 익명 플레이어 선택 → 회차 선택으로 조회할 수 있습니다. 캐릭터·에피소드·기간·상태·방식 필터도 지원합니다. 동명이인은 브라우저 단위 익명 번호로 구분하며, 새 게임은 새 회차 번호를 가집니다. 같은 요청 재전송은 하나의 기록에 시도 횟수로 남습니다. 세이브를 되돌린 뒤 새로 보낸 메시지는 새 기록입니다.

기록은 `private-data/conversations.sqlite`에 저장되어 서버 재시작 후에도 유지됩니다. 30일 경과 기록은 시작·조회·전송 및 주기적 정리 때 삭제됩니다. 관리자에서 플레이어 전체 기록을 삭제하면 동의도 해제됩니다. 게임 세이브와 갤러리는 별개입니다.

관리자 인증은 비밀번호 해시, 8시간 서버 세션, HttpOnly 쿠키, 로그인 시도 제한과 요청 위조 방어를 사용합니다. 서버 API 키·시스템 프롬프트·인증 헤더·IP를 대화 로그에 덤프하지 않습니다.

현재 기본 실행은 로컬 접속용입니다. 다른 사람의 기록을 모으려면 사람들이 접속하는 공통 서버에 배포해야 합니다. 외부 운영 시 `HOST`·HTTPS `PUBLIC_ORIGIN`과 영구 `GAME_DATA_DIR`를 구성해야 하며, 여러 서버나 임시 파일시스템 환경은 공통 영구 DB 구성이 별도로 필요합니다. 이번 작업에서 외부 배포는 하지 않았습니다.

## 주요 파일과 확인

- `public/episodes.js`: v4의 7편 대본·선택·공통 수리와 후속 연구 제안
- `public/ending-v4.js`: 현재 엔딩 제목·짧은 아침 대본. 이전판 엔딩은 data.js에 유지
- `public/narrative.js`: v4 진행과 이전판 분기
- `public/narrative-v3.js`: 이전 7편 시나리오 저장용 진행. 초기 v1의 장소 선택·데이트 UI·3인 충돌·디버깅 미니게임은 제거했으며 해당 저장은 점수·기억을 보존해 가까운 호환 장면으로 연결합니다.
- `public/engine.js`: 호감도·기억·엔딩·저장 검증
- `public/app.js`: 화면·저장·입력·동의 흐름
- `public/story-expressions.js`: 고정 대사의 상황별 표정과 선택 후 반응. 표정은 같은 장면의 주인공·나레이션 대사에서도 유지하며 명시적인 대사 `emotion`·`expressions`로 조정할 수 있습니다.
- `src/dialogue.js`, `src/openai.js`: AI 상황·응답 검증·연결
- `src/log-store.js`, `src/log-routes.js`: 기록·관리자 인증 API
- `public/admin.*`: 관리자 화면

`npm run check`로 문법을, `npm test`로 시나리오·저장·API·보안 동작을 확인합니다. 결과는 `검증 결과.md`에 정리합니다. `수정plan.md`는 완료 기록으로 남겼으며 이후 삭제해도 됩니다.
